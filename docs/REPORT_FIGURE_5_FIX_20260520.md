# Report Figure 5.1/5.2 Export Fix - 2026-05-20

## Problem

The generated Word report could still receive stale ANSYS graphics for Figure 5.1 and Figure 5.2.  The post-only graphics pass converted `/IMAGE,SAVE` to PNG, but the source plot state could be polluted by earlier `NPLOT`, `/REPLOT`, or `PLLS` line-stress contour commands.  As a result:

- Figure 5.1 could be a replayed node plot instead of an explicit finite-element model plot.
- Figure 5.2 could be a stress cloud or a reused whole-model image instead of a dedicated tray-arm model image.

## Fix

- `core/ansys/figure_export.py`
  - Exports `SHITI.PNG` and `TBMODEL.PNG` before the standard result-contour postprocessor runs.
  - Uses a clean `/PREP7` model graphics context for both report model figures.
  - Skips the original `SHITI` and `TBMODEL` `/IMAGE,SAVE` points in `generated_post_figure_export.mac`, so later POST1 result graphics cannot overwrite them.
  - Keeps all Appendix B/C stress cloud figures source-derived from the converted postprocessor stream.

- `templates/apdl/post_extract_s2.mac.j2`
  - Wraps the native SHITI/TBMODEL image save blocks in `/PREP7` and returns to `/POST1`.
  - Selects Fig. 5.2 tray-arm elements from the documented type families:
    - front side: `10*layer+2/3/4`
    - back side: `200*layer+2/3/4`
  - Falls back to whole-model `EPLOT` only when a historical database has lost type metadata, preventing empty or stale plots.
